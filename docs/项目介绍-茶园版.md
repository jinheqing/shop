## 一、这套系统到底是什么？

一句话：**这是一套为咱们量身定做的高端茶叶跨境电商 + 直播 + 溯源 + 顾问服务一体化平台**。

它服务的目标市场是 **英国和欧洲**，解决的核心问题是：

> 让英国客户不再是在亚马逊/速卖通上盲选几百个差不多的茶叶商品，而是能像看纪录片一样"认识"这泡茶 — 顾问一对一沟通定制、直播看到采摘和制作过程、每一批都有 SGS 质检报告、顾问全程跟踪直到签收。

### 咱们的产品策略：两步走

**第一步（当下）— 用滇红打入场战**

英国是世界上最大的红茶消费国。英国人从小喝 Assam、Darjeeling、Earl Grey 长大，红茶是刻在骨子里的日常。而咱们云南的 **滇红（Yunnan Black Tea）** 口感接近 Assam（浓郁、麦芽香、适合加牛奶），但又有云南特有的蜜糖香和回甘，英国老钱喝一口就能懂 — 这是他们熟悉的味道，但比 Assam 更温润、更有层次。

> JING Tea 卖 Assam Breakfast £30/100g，咱们用同档甚至更好的滇红切入，定价 £25-35/100g，加上直播和顾问服务，客户很难不动心。

**第二步（中期）— 用普洱做差异化突破**

等咱们靠滇红建立起第一批客户信任、有了品牌口碑之后，再推出普洱茶。普洱在英国目前还是小众，JING Tea 只拿它当边缘品类卖（搜索 "pu-erh" 出来的商品只有 2-3 个）。但英国的高端茶客已经开始对"能陈化、越放越好喝"的茶感兴趣 — 这正是普洱的独特卖点，也是咱们和所有竞争对手拉开差距的杀手锏。

> 亚马逊上搜 "pu-erh"，出来的都是十几英镑的大路货。咱们要做的是让英国客户第一次喝到"顾问一对一讲解 + 直播看制作 + SGS 报告 + 完整溯源"的高端普洱茶。

**一句话：先用他们听得懂的语言（滇红）进门，再讲他们没听过的故事（普洱）。**

**系统由三个端组成：**

| 端 | 用户 | 入口 | 技术 |
|---|---|---|---|
| 公共站点 | 英国客户（C 端） | `https://tea.7758521.sbs/` | Vue 3 双语网站 |
| 后台管理 | 运营/管理员 | `https://tea.7758521.sbs/admin/` | Vue 3 双语管理后台 |
| 手机 App | 茶园工作人员 + 顾问 | Flutter App（iOS/Android） | 原生移动应用 |

后端统一由一套 Go 语言服务驱动，数据库用 PostgreSQL，直播用 LiveKit + MediaMTX。

## 二、和竞争对手的对比

### 2.1 对标对象

我们主要对标两类竞争者：

1. **国际电商平台** — Amazon（亚马逊）、AliExpress（速卖通）
2. **英国本土高端茶品牌** — JING Tea（2004 年创立于伦敦，希尔顿、四季酒店供应商）

### 2.2 和 Amazon / AliExpress 的区别

亚马逊和速卖通本质上都是 **流量集市** — 几千个卖家在上面卖茶，平台只负责"让你搜到"和"快速送到"。

| 对比项 | Amazon（亚马逊） | AliExpress（速卖通） | 我们的系统 |
|--------|-----------------|---------------------|-----------|
| **卖家数量** | 数千家，互相压价 | 数万家，互相压价 | 只有我们自己的品牌，没有竞争 |
| **价格** | 中等偏高（平台抽成 + 运费） | 极低，但运费有时比茶还贵 | 中高端定价，一对一顾问服务 |
| **客户感知** | "这茶好像还行，200 多条评论" | "能不能喝？评论里有中文差评" | "这茶的产地我知道、制茶师傅我见过、直播我看过" |
| **定制化** | ❌ 选规格下单就完了 | ❌ 不能改任何东西 | ✅ 顾问一对一，可以选原料、茶型、花熏、包装、卡片 |
| **直播** | ❌ 没有 | ❌ 没有 | ✅ 6 种直播场景，24/7 茶山慢直播、品鉴直播、交付验货直播 |
| **质检** | 可选，大部分没有 | 基本没有 | ✅ 每批强制 SGS 欧洲食品安全报告 |
| **溯源** | 无 | 无 | ✅ 每批有完整溯源：茶园地址、采摘日期、制茶师傅、存储仓库 |
| **顾问** | ❌ 没有，只有客服 | ❌ 没有 | ✅ 一对一顾问，从下单到签收全程跟进 |
| **语言** | 英语单一 | 英语单一 | ✅ 中英文自适应（浏览器中文显示中文，英文显示英文） |
| **合规** | 部分合规，GDPR 是平台级的 | 合规较弱 | ✅ 完整 GDPR 合规，客户可以申请导出/删除自己所有数据 |
| **支付** | Amazon Pay / 信用卡 | 支付宝 + 信用卡 | ✅ 2Checkout / PayPal（欧洲主流支付） |
| **物流** | Prime 1-3 天，但茶叶保鲜难 | 10-20 天，从国内发 | ✅ 正规报关 → 国际物流 → 英国本地派送，可追溯 11 个状态 |
| **客户关系** | 平台不允许私域 | 平台不允许私域 | ✅ 自己的用户数据、用户分组、IM 私域聊天 |
| **上架成本** | FBA 费 + 平台抽成约 15% | 佣金较低但引流贵 | ✅ 零平台抽成，直接面向客户 |
| **品牌形象** | 大家都是"那个卖茶的" | 大家都是"那个便宜的" | ✅ 英国高端滇红 + 普洱茶品牌，和 JING Tea 同档 |

**一句话总结**：亚马逊/速卖通让你在几千个卖家里选最划算的。我们让客户选"最有故事、最有保障、最有服务"的。

### 2.3 和 JING Tea（英国最大高端茶品牌）的对比

JING Tea 是我们最直接的竞争对手 — 2004 年创立于伦敦，希尔顿、四季酒店、文华东方等高端酒店的茶供应商，在英国已经做了 22 年，口碑和渠道都很成熟。

JING Tea 网站（`jingtea.com`）用的是 Shopify，产品以红茶、绿茶、白茶、乌龙茶为主，普洱茶只是很小的一部分。价格定位：散茶 £20-55 / 100g，礼盒 £80-150。

| 对比项 | JING Tea | 我们的系统 |
|--------|----------|-----------|
| **品牌历史** | 2004 年创立，22 年沉淀 | 新品牌，但背后有中国茶园资源 |
| **产品重心** | 红茶（Assam、Earl Grey）、绿茶、白茶、乌龙茶为主，普洱茶只是边缘 | **两步走**：① 先用滇红（Yunnan Black Tea）切入 — 英国老钱熟悉的 Assam 风格但更温润有蜜糖香 ② 再用普洱突破 — 在 JING Tea 只卖 2-3 款边缘普洱的市场里建立高端普洱专属品牌 |
| **产品形式** | 预包装现货，不能定制 | ✅ Bespoke 定制系统：客户选原料、茶型、花熏、包装、卡片文字、数量 |
| **定价方式** | 固定价格，按品类分档 | ✅ 定制定价：不同原料（古树 vs 台地）、不同工艺（晒青 vs 烘青）、不同数量对应不同价格 |
| **直播** | ❌ 没有任何直播 | ✅ 6 种直播场景：24/7 茶山慢直播、品鉴直播、交付验货直播、定制私密直播 |
| **质检报告** | 提了可持续性和有机认证，但没有 SGS 检测报告展示 | ✅ 每批强制 SGS 欧洲食品安全报告，在线可查可下载 |
| **溯源** | 有"产地图"（如 Jingshan Garden, China），但只到茶山名字 | ✅ 完整溯源页面：茶园地址、采摘日期、制茶师傅姓名、存储仓库、SGS 报告编号 |
| **顾问服务** | ❌ 没有一对一顾问 | ✅ 顾问从沟通定制 → 报价 → 跟进生产 → 安排直播 → 验货 → 签收，全程跟进 |
| **即时聊天** | ❌ 只有邮件和电话客服 | ✅ 自研 IM 聊天，支持中英实时互译 |
| **多语言** | ❌ 只有英文（日本站 mikasa-net.co.jp 是第三方代理） | ✅ 中英文自适应 |
| **物流跟踪** | 只有"已发"和"签收"两个状态，靠物流商网站查 | ✅ 11 个状态机：付款 → 报关 → 生产 → 报检 → 清关 → 运输 → 签收，客户在自己账户里实时看 |
| **国际化物流** | 用现成物流商，不能自己控制报关清关 | ✅ 系统内置 HS Code、报关资料、清关状态跟踪 |
| **SaaS vs 自有** | 用 Shopify，改不了功能 | ✅ 完全自有，想加什么功能加什么 |
| **移动端 App** | ❌ 没有 | ✅ iOS + Android App，茶园工作人员和顾问可以移动办公 |
| **客户分组** | 有积分计划（Rewards Programme），但只是积分 | ✅ 可以按消费额、注册时间、购买历史自动分组，给不同组开放不同商品/直播特权 |
| **GDPR** | 部分合规，靠 Shopify | ✅ 完整 DSAR（数据主体访问请求）流程，客户可以申请导出/删除所有数据 |

**我们对 JING Tea 的核心优势可以浓缩为 6 句话：**

> 1. 他们卖预包装茶叶，我们卖 **顾问一对一定制化茶叶**
> 2. 他们只有图片和文字介绍，我们有 **直播让客户亲眼看到茶山和制作过程**
> 3. 他们只说"来自云南"，我们能给出 **制茶师傅名字 + SGS 报告 + 采摘日期**
> 4. 他们是 SaaS 改不了，我们是 **自有系统，想加什么功能加什么**
> 5. 他们只有英文，我们是 **中英双语自适应**
> 6. 他们做了 22 年但不做高端普洱 — **我们先用滇红进门，再用普洱打他们没有的市场**

## 三、功能总览（系统能做哪些事？）

### 3.1 给客户的（C 端公共站点）

| # | 功能 | 说明 |
|---|------|------|
| 1 | **双语自适应网站** | 浏览器中文显示中文，英文显示英文；所有页面中英双语 |
| 2 | **魔法链接登录** | 不用记密码，输入邮箱收到邮件点一下就登录（欧洲客户习惯这种方式） |
| 3 | **定制化茶叶（Bespoke）** | 客户可以选茶类（滇红优先 → 后续扩展普洱）、茶型（散茶/饼/砖/沱）、是否做花熏（茉莉/桂花/兰花）、内外包装、卡片文字 — 顾问一对一沟通 |
| 4 | **在线报价单（Quote）** | 定制完成后生成正式报价单，客户在线查看、确认、支付 |
| 5 | **直播中心** | 首页展示当前直播、即将开播的直播日历、过往回放 |
| 6 | **茶山慢直播（24/7）** | 摄像头装在茶山上，客户随时点开看真实的茶山风光和天气 |
| 7 | **品鉴直播** | 顾问用 OBS 直播品茶过程，讲解香气口感 |
| 8 | **交付验货直播** | 茶叶装好箱准备发运前，开直播让客户亲眼确认装箱、贴标签过程 |
| 9 | **完整溯源页** | 每一批茶有专属溯源页面：茶园地址、采摘日期、制茶师傅名字、SGS 质检报告、存储仓库 |
| 10 | **订单中心** | 客户能看到自己订单的完整状态：从付款到清关到签收，11 个状态实时更新 |
| 11 | **电子发票** | 在线查看和下载电子发票（PDF） |
| 12 | **即时聊天（IM）** | 客户可以直接和顾问聊，支持中英互译 |
| 13 | **GDPR 数据保护** | 客户可以申请导出自己的所有数据（DSAR），可以申请删除账号 |
| 14 | **Cookie 同意** | 符合欧盟 Cookie 法规 |
| 15 | **品质（Quality）页面** | 展示 SGS 质检报告详情和检测项目 |

## 五、直播系统详解（6 种场景 × 3 种推流方式）

直播是咱们系统最有辨识度的功能，也是让英国客户"真正看见茶"的关键。

### 6 种直播类型

| 类型 | 场景 | 推流方式 | 谁来看 |
|------|------|----------|--------|
| **茶山慢直播** | 24/7 摄像头对着茶山 | 固定摄像头 RTMP 推流 | 所有人可看 |
| **品鉴直播** | 顾问用 OBS 直播品茶讲解 | OBS Studio RTMP 推流 | 所有人可看 |
| **开放预约直播** | 提前发布直播日历，客户预约 | App/WebRTC 或 OBS | 注册客户可看 |
| **客户指定场景** | 某客户要求看自己那批茶的制作 | App 或 OBS | 仅该客户可看 |
| **交付验货直播** | 装箱前开直播让客户确认 | App 一键开播 | 仅该订单客户可看 |
| **定制私密直播** | 针对 Bespoke 订单的专属直播 | App 或 OBS | 仅该订单客户可看 |

### 直播的"高大上"之处

- **实时翻译字幕**：顾问说中文 → 英国客户看到英文字幕（实时翻译服务处理）
- **录制回放**：直播结束自动生成回放链接，客户可以反复看
- **直播日历**：首页展示即将开始的直播，客户可以预约
- **可见性控制**：公开 / 仅注册 / 特定用户组（VIP 专属直播）
- **OBS 推流配置**：管理员后台填一次推流域名，顾问在后台创建直播时自动生成推流地址和密钥

## 六、订单 11 个状态全流程（这是客户感知到的核心价值）

亚马逊/速卖通/JING Tea 都只有"已发"和"签收"两个状态。咱们有 11 个，客户可以清楚知道：我的茶现在在哪一步？

```
① ordering     客户正在下单
      ↓
② paid         付款成功 ✓
      ↓
③ pending_declaration  正在准备报关资料
      ↓
④ producing    茶园正在生产（客户可以申请看生产直播）
      ↓
⑤ ready_for_production 生产完成，准备发运
      ↓
⑥ pending_customs  等待清关
      ↓
⑦ customs_clear    清关通过 ✓
      ↓
⑧ shipped          已发往英国 ✓
      ↓
⑨ completed        客户签收 ✓
      ↓
（中间任何阶段都可以 → cancelled 取消
    shipped 之后还可以 → disputed 争议）
```

**关键点：没有跳步。** `paid` 不能直接到 `completed`，必须经过生产 → 报关 → 清关 → 运输。这样客户收到货时，能清晰感受到"我的茶真的是刚做出来的，不是仓库里压了几年的旧茶"。

## 七、技术亮点（给感兴趣的朋友看）

| 亮点 | 说明 |
|------|------|
| **全栈 Go + Vue + Flutter** | 后端 Go（高性能）、前端 Vue 3（现代）、移动端 Flutter（一套代码跑 iOS + Android） |
| **PostgreSQL + Redis** | 数据库 PostgreSQL（带 JSONB，支持灵活的定制商品字段），Redis 做缓存和魔法链接存储 |
| **自有直播系统** | LiveKit（SFU）+ MediaMTX（WebRTC + RTMP 网关），完全自建，不依赖抖音/YouTube/B站 |
| **实时翻译引擎** | Python FastAPI 服务，支持 IM 聊天和直播字幕的中英互译 |
| **强制 SGS 报告** | 每批茶必须上传 SGS 质检报告 PDF，关联到溯源页面，客户在线可查 |
| **完整溯源** | 每批茶有 product_token，溯源页面包含茶园地址、采摘/制作日期、制茶师傅、SGS 报告编号、存储仓库 |
| **GDPR 合规** | 完整 DSAR（数据主体访问请求）流程：客户可以申请导出/删除自己的所有数据，有 30 天 SLA 跟踪 |
| **IP 定位** | 自动识别客户 IP，显示在后台客户列表（知道客户来自伦敦还是伯明翰） |
| **魔法链接登录** | 无密码登录，通过邮件里的一次性链接完成，比密码更安全也更方便 |
| **审计日志（独立数据库）** | 所有操作记录写入独立 PostgreSQL 实例，不可软删除，符合欧洲合规要求 |
| **容器化部署** | Docker Compose 一键部署：Go 后端 + PostgreSQL + Redis + MediaMTX + Translate Service |
| **配置全后台化** | 邮件 API Key、OBS 推流域名、支付网关 — 全部在 System Settings 页面改，不写死代码 |
| **用户组系统** | 可以自动把客户分组（如"累计消费 ≥ £500 → VIP"），给不同组开放不同直播/商品 |
| **WebSocket IM** | 自研即时聊天，支持顾问和客户实时对话，已接入实时翻译 |
| **SSL 全链路** | HTTPS + SNI 代理，一个 IP 跑多个域名，互不干扰 |
