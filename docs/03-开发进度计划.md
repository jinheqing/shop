| `tea-system/internal/config/database.go` | GORM 连接两个 PostgreSQL 实例（业务库 + 审计库） |

**关键约束（AI 必须遵守）**：
- 所有表必须有 `id bigserial primary key`、`created_at timestamp not null`、`updated_at timestamp not null`、`deleted_at timestamp`（soft delete）
- `payment_transactions.gateway_transaction_id` 必须建 UNIQUE 索引（数据库层幂等）
- `custom_products.product_token` UNIQUE
- `orders.order_no` UNIQUE
- 实体间的 FOREIGN KEY 在 GORM struct 里用 `gorm:"foreignKey:XXX"` 标注
- **Node struct 里不要加 ssh_password 字段**（注释说明不持久化，仅部署期间内存存在）

**执行命令**（AI 必须执行）：
```bash
cd /workspace/tea-system
# 安装 golang-migrate
go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@latest
# 生成迁移文件
migrate create -ext sql -dir migrations -seq init_schema
# 编写 up.sql 和 down.sql（按开发设计文档 DDL）
# 运行迁移（需要临时 PostgreSQL 实例，可以用 docker run postgres:16 启一个临时的）
docker run -d --name temp-pg -e POSTGRES_DB=tea_system -e POSTGRES_PASSWORD=test -p 5432:5432 postgres:16
migrate -path migrations -database postgres://postgres:test@localhost:5432/tea_system?sslmode=disable up
# 验证迁移成功
docker exec temp-pg psql -U postgres -d tea_system -c "\dt"
# 清理临时容器
docker stop temp-pg && docker rm temp-pg
```

**验收标准**：
- ✅ `docker exec temp-pg psql -c "\dt"` 能看到所有 17 张表（不包括 audit_logs，那个独立库）
- ✅ `\d payment_transactions` 能看到 `gateway_transaction_id` 有 UNIQUE 约束
- ✅ 迁移 down.sql 能完整回滚
- ✅ GORM AutoMigrate 能基于 models/ 目录下的 struct 生成相同的 schema（开发阶段验证）

## Step 8: 定制报价 CRUD + token 生成 + 版本管理

**读什么文档**：开发设计文档 → 第二部分后端 API（定制报价所有 endpoint + POST 完整 JSON schema）→ 第三部分管理后台（创建报价表单 26 字段对齐表）

**目标**：POST /custom-products 接受完整 26 字段 JSON，生成产品 + token，版本管理正确。

**输出文件**：

| 文件 | 说明 |
|------|------|
| `internal/api/handlers/custom_product.go` | 报价 CRUD（POST 完整 schema 校验 + GET/GET:id/PUT/POST:publish/POST:review） |
| `internal/service/custom_product_service.go` | 版本管理（PUT 时 version +1）+ 产品 token 生成（64 位 URL-safe） |
| `internal/repository/custom_product_repo.go` | CustomProduct CRUD |

**关键约束**：
- POST 时必须校验所有 NOT NULL 字段
- PUT 时必须生成新版本（version 自动 +1），旧版本保留（软删除或新表）
- publish 时生成 product_token（64 位随机）
