# 推荐人功能 · 完整使用手册

> 本文档给**后台管理员、顾问、茶园运营**用。讲清楚推荐人功能是什么、怎么用、怎么配、注意什么。
> 最后更新：2026-09-19

---

## 一、这是什么

### 一句话

**我们不做电商式返利（"输码拿 10% off"），我们做的是英国高端品牌在用的 Name Share（名字分享）模式 — 老客户跟朋友说"我叫 Peter，你结账时输入我名字就行"，顾问在后台收到后给老客户发感谢礼物 + 累计推荐数到 3 个自动进 KOL 伙伴特权组。**

### 为什么和电商返利不一样

| 电商返利（我们绝对不做） | Name Share（我们做的） |
|------------------------|----------------------|
| 公开推荐码到处转发 | 只在 WhatsApp/Email 私域传 |
| 新老客户都拿折扣 | 不给折扣，给礼物 + 身份特权 |
| 像代购、像传销 | 像私人引荐、像私人俱乐部 |
| 快消品玩法 | MATCHESFASHION / Nespresso 在用 |

### 核心数据来源（我们为什么选这个模式）

- **Mention Me**（服务 400+ 英国高端品牌的推荐营销平台）数据：49% 的高端品牌推荐来自 Name Share（名字分享），远高于短链分享
- Mention Me 白皮书：推荐渠道贡献 **10–30% 新客户获取**；推荐客户多花 25%、LTV 是普通客户 2 倍、3 倍更可能再推荐
- **Altiant GLAM Monitor Q2 2026**（全球 HNWI 研究）：英国高端消费者最讨厌公开推荐码和返利

### 两种触发方式（全部可选，不强制）

| 方式 | 用户怎么填 | 后端怎么匹配 |
|------|-----------|-------------|
| **① 名字分享** | 新客户注册时，展开 `<details>` 折叠框 → 选 "A friend recommended" → 输入朋友的名字 | 模糊匹配 `users.name`（ILIKE），取最新一个 → 匹配上了自动建 Referral 记录 |
| **② 专属短链** | 老客户在 Account 页 "Share The Tea" Tab 复制专属短链（如 `/r/AB3X9K2P`）→ 通过 WhatsApp 私下发给朋友 | 新客户点链接带 `?r=AB3X9K2P` → 注册时前端自动带到 payload 里 → 后端精确匹配 `users.referral_short_code` → 建记录 |

### 奖励机制（给的是礼物 + 身份，不是折扣）

| 触发条件 | 推荐人得到 |
|----------|-----------|
| 朋友下单金额 ≥ `referral_min_order_amount`（默认 £100） | 顾问手动安排一个**专属礼物**（如一小罐 2018 年古树普洱试喝装） |
| 累计 3 个朋友都下单达标 | 自动拉进 **KOL 伙伴** 用户组 → 闭门品鉴会 / 限量茶先购 / 茶园参观邀请 / 年度私宴 |

## 二、完整业务流程（从上到下）

```
老客户（已经在我们这买过茶的人）
       │
       │ 方式一：跟朋友聊天
       │  → "我最近发现一家做云南古树茶的，特别好，你可以去看看。
       │     我叫 Peter，结账时输入我名字就行"
       │
       │ 方式二：Account 页 → Share The Tea Tab → 复制专属短链
       │  → 通过 WhatsApp 私发给朋友（不发朋友圈）
       ▼
朋友（新客户）
       │
       │ 打开 /magic-link?r=AB3X9K2P（方式二）
       │ 或直接打开 /magic-link
       │
       │ 注册/登录 → 展开 "How did you hear about us?"
       │         → 选 "A friend recommended"
       │         → 输入 "Peter"
       ▼
后端自动匹配（MagicLinkRequest 里）
       │
       │ matchAndCreateReferral() 尝试匹配：
       │   ① 如果带了 referral_code → 精确匹配 referral_short_code
       │   ② 如果带了 referrer_name → ILIKE 模糊匹配 users.name
       │
       │ 匹配成功 → 自动建 Referral 记录 + 更新 users 表
       │ 匹配不上 → ReferrerName 留着，顾问后台手动关联
       ▼
朋友下单 → 支付成功（2Checkout / PayPal webhook）
       │
       ▼
UpdateReferralOnOrderPaid() 自动触发
       │
       │ ① 找这个新客户的 Referral 记录
       │ ② 更新 friend_order_id / friend_order_amount
       │ ③ 检查 system_config.referral_min_order_amount（默认 £100）
       │    → 订单没到门槛 → 结束
       │ ④ 订单到了 → 数推荐人累计有多少个有效推荐
       │ ⑤ 检查 system_config.referral_count_to_vip（默认 3）
       │    → < 3 → 结束（顾问手动在后台发感谢邮件 + 礼物）
       │    → ≥ 3 → 自动把推荐人加进 KOL 伙伴 用户组
       ▼
顾问后续操作
       │
       │ · 登录 admin-dashboard → Referrals 页面
       │ · 看到 "Pending Rewards" 的条目
       │ · 手动开一个定制小单（礼物）
       │ · 点 "Trigger Now" 按钮 → 标记奖励已触发
       ▼
推荐人（Peter）
       │
       │ · 收到礼物 → 更愿意推荐更多朋友
       │ · 如果进了 KOL 伙伴组 → 在 Account 页能看到自己是 VIP
       │ · 顾问会主动通知："感谢你介绍了 3 位朋友来喝茶，我们为你准备了..."
```

## 三、部署后初始化（必须做）

GORM AutoMigrate 会自动建表和加字段，下面 3 件事是**需要手动做的**：

### 步骤 1：后台创建 "KOL 伙伴" 用户组

入口：admin-dashboard → Live Streaming → User Groups → Create

| 字段 | 填什么 |
|------|--------|
| Name | `KOL 伙伴` |
| Description | "通过朋友推荐加入的老客户圈层 — 闭门品鉴会 / 限量茶先购 / 茶园参观" |
| Privileges | 勾选：`private_masterclass`、`preorder_priority`、`offline_invite`、`offline_garden_tour:menghai`（或其他茶园批次）、`vip_concierge`、`deep_traceability` |
| Reciprocal | 留空或填其他合作俱乐部的 key |

### 步骤 2：配置 SystemSettings（可选，有默认值）

入口：admin-dashboard → System → System Settings → PUT /api/v1/system/config/:key

| Key | 默认值 | 说明 |
|-----|--------|------|
| `referral_min_order_amount` | `100` | 朋友下单金额达到这个数才算"有效推荐"，才会触发奖励检查 |
| `referral_count_to_vip` | `3` | 累计多少个有效推荐自动进 KOL 伙伴组 |

> 不配置也能跑 — 代码里 hardcode 了默认值。配了就覆盖。

### 步骤 3：检查 users 表已有数据的短链

新用户注册时系统会自动生成 `referral_short_code`（8 位 base36，易读无混淆字符）。但已存在的老客户（部署前注册的）没有这个 code。

**处理方式**：顾问在后台手动给老客户生成 code — 在 admin-dashboard 暂时没有一键生成按钮，但可以用 SQL 快速补：

```sql
UPDATE users SET referral_short_code = UPPER(SUBSTRING(MD5(CAST(id AS TEXT) || 'tea'), 1, 8))
WHERE referral_short_code IS NULL;
```

> 这个 SQL 只是临时用的。代码里的 `genShortCode()` 是生产级的确定性生成（基于 id × 常数，去易混字符集），更安全。长期看应该在 admin-dashboard 用户详情里加个"生成专属短链"按钮。

## 四、admin-dashboard 操作手册

### 4.1 Referrals 页面

入口：Live Streaming → **Referrals**（新增页面）

#### 页面布局

| 区域 | 内容 |
|------|------|
| 顶部统计卡片 | 4 个数字：Total Referrals / Rewards Triggered / Pending Rewards / No Order Yet |
| 搜索过滤条 | Referrer 名字模糊 / Referred 名字模糊 / ☑ Only rewarded / ☑ Pending reward / 搜索 / Reset |
| 表格 | ID / Referrer（名字 + User #）/ Referred（名字 + User #）/ Source（Name Share / Short Code / Manual）/ Friend Order（金额 + 订单号）/ Reward（Triggered / Pending / Waiting）/ Created / Actions |
| Create 按钮 | 手动创建推荐关系（当名字匹配不上系统里的用户时） |

#### 手动创建推荐关系（顾问常用操作）

**什么时候用？** 顾问收到邮件或 IM 消息说 "张总介绍我来的"，但系统自动匹配没匹配上（张总名字可能是 Zhang / Peter Zhang / Zhang Wei 三种写法）。

**操作步骤：**
1. 点右上角 **+ Add Referral**
2. **Referred User ID** = 新客户的 User ID（在 Users 页面能查到）
3. **Referrer User ID** = 如果张总在系统里就填他的 User ID；不知道就留空，只输名字
4. **Referrer Name** = "张总"
5. **Source** = `manual`
6. **Notes** = 随便写点上下文（"IM 聊的，张总是第二次推荐"）
7. 点 Create → 自动同步到 users 表

#### 手动触发奖励

**什么时候用？** 朋友下单达标了（Pending 状态），顾问已经手动给老客户安排了礼物（开了个 £0 的定制小单），现在要在系统里标记一下让整个流程闭环。

**操作步骤：**
1. 找到 Pending 的那一行
2. 点 **Trigger Now**
3. 弹窗确认 → 点 OK
4. Reward 列变成绿色 ✓ Triggered，显示触发时间

#### 删除推荐关系

**什么时候用？** 发现匹配错了（比如两个人同名被自动匹配成另一个人）。

**操作步骤：** 直接点 Delete。删除后会同步清理 users 表里的 referrer_user_id / referrer_name 字段。

### 4.2 Users 页面（增强）

Users 页面的每个用户详情里，应该能直接看到：
- `referral_source`（怎么找到我们的）
- `referrer_name`（推荐人名字）
- `referrer_user_id`（推荐人在系统里的 ID）
- `referral_short_code`（专属短链 code）
- 这个用户自己推荐了多少人、其中多少个下单达标

> **TODO**：当前 admin-dashboard 的 Users.vue 可能还没显示这些字段。如果没有，后续补上。

### 4.3 User Groups 页面

和推荐人直接相关的是 AutoRule 自动分组机制。当前 UserGroups 页面的 AutoSync 按钮已经支持自动按规则分组。

| AutoRule Key | 触发条件 | 自动进哪个组 |
|--------------|---------|------------|
| `referral_count ≥ 3` | 累计 3 个有效推荐（朋友下单 ≥ £100） | KOL 伙伴 |

> 当前代码里这个是在 `UpdateReferralOnOrderPaid` 里**硬编码**的（查 "KOL 伙伴" 组名 + 检查 `referral_count_to_vip` 配置）。未来可以扩展成 UserGroups 页面配置 AutoRule 表达式（如 `referral_count >= 3 AND total_spent >= 500`）。

## 五、顾问日常工作流（怎么用这个功能）

### 场景 A：新客户在 IM 里说 "张总介绍我来的"

| 步骤 | 操作 |
|------|------|
| 1 | 先让客户走 MagicLink 注册（如果还没注册） |
| 2 | 注册后系统自动匹配 → 看 Referrals 页面有没有自动建记录 |
| 3a | **有记录** → 顾问在 IM 上给张总发一封感谢："您朋友 XXX 已经来注册了，感谢您的介绍" |
| 3b | **没记录** → 顾问手动创建 Referral（Referred User ID + Referrer Name） |
| 4 | 后续朋友下单达标后，系统自动算张总的累计推荐数 |

### 场景 B：推荐人朋友下单达标了（Pending 状态）

| 步骤 | 操作 |
|------|------|
| 1 | 顾问每天/每周查一次 Referrals 页面的 **Pending Rewards** 列表 |
| 2 | 选一个 Pending 的推荐人 |
| 3 | 在 Bespoke Products 里开一个**礼物小单**：产品是一小罐试喝装，总价 £0（或成本价），状态设为 "gift" |
| 4 | 在 Referrals 页面点 **Trigger Now**，标记奖励已触发 |
| 5 | 顾问给推荐人发邮件："感谢您介绍 XXX 来喝茶，我们给您寄了一个小礼物..." |

### 场景 C：推荐人累计 3 个有效推荐了

| 步骤 | 操作 |
|------|------|
| 1 | 系统自动把他加进 "KOL 伙伴" 用户组（在 UserGroups → Members 页面能看到） |
| 2 | 顾问主动发邮件/IM："感谢您介绍了 3 位朋友来喝茶，我们邀请您加入我们的 KOL 伙伴圈层..." |
| 3 | 后续顾问可以给这个组的成员单独推限量茶、闭门品鉴会 |

## 六、用户端体验（新客户 & 老客户）

### 6.1 新客户注册（MagicLink 页面）

入口：`https://tea.7758521.sbs/magic-link`

页面上有一个**低调折叠框**（`<details>`），默认收起，标题灰色小字：

> How did you hear about us? *(optional)*

点开后：
- 下拉选（friend / youtube / search / other）
- 选了 friend 才会显示 "Your friend's name" 输入框
- 如果是点了短链过来的（URL 带 `?r=XXX`），页面会自动检测并显示一行小字 "We detected a referral link — thank you to your friend!"

### 6.2 老客户 Account 页（Share The Tea Tab）

入口：登录后 → `/account` → 最后一个 Tab **Share · The · Tea**

| 区域 | 内容 |
|------|------|
| 专属短链 | `/r/AB3X9K2P`（可点 Copy · Link 一键复制） |
| 3 格统计 | Friends Invited / With Orders / Rewards Sent |
| 推荐列表 | 每一行是一个被推荐的朋友：名字 + 朋友下单金额 + ✓ Thank you sent（如果已经触发了奖励） |
| 底部空状态 | "No referrals yet. Share your favourite tea with a friend — your name travels farther than any advertisement." |

**文案刻意做的克制** — 没有"赚积分""拿返利"这类词，只有 "Share" / "Thank you"。

## 八、数据库表结构

### referrals 表（新建）

```sql
CREATE TABLE referrals (
    id                  BIGSERIAL PRIMARY KEY,
    referrer_user_id    BIGINT REFERENCES users(id),          -- 推荐人（可能为空）
    referrer_name       VARCHAR(100) NOT NULL,                -- 推荐人名字（冗余存）
    referred_user_id    BIGINT NOT NULL REFERENCES users(id) UNIQUE,  -- 被推荐人（唯一）
    referred_name       VARCHAR(100) NOT NULL,                -- 冗余存
    source              VARCHAR(20) DEFAULT 'name_share',     -- name_share / short_code / manual
    friend_order_id     BIGINT,                               -- 朋友下的订单
    friend_order_amount DOUBLE PRECISION DEFAULT 0,           -- 朋友下单金额
    reward_triggered_at TIMESTAMPTZ,                          -- 奖励触发时间
    created_by_staff_id BIGINT,                               -- 创建人（顾问手动建的才填）
    notes               TEXT,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at          TIMESTAMPTZ
);
```

### users 表（新增 4 列）

```sql
ALTER TABLE users ADD COLUMN referral_source    VARCHAR(50);
ALTER TABLE users ADD COLUMN referrer_name      VARCHAR(100);
ALTER TABLE users ADD COLUMN referrer_user_id  BIGINT REFERENCES users(id);
ALTER TABLE users ADD COLUMN referral_short_code VARCHAR(20) UNIQUE;
```

## 十、绝对不能做的事（团队共识）

这 5 条是**品牌底线**，任何人不能在代码里加，也不能在运营里做：

| # | 绝对不能做 | 为什么 |
|---|----------|-------|
| 1 | **公开推荐码**（在 Instagram / Facebook / Twitter 发） | 像代购、像传销、拉低品牌。老钱只在私域传 |
| 2 | **推荐返现 / 推荐折扣** | 快消品玩法。高端品牌用礼物和特权，不用现金 |
| 3 | **朋友下单就给推荐人自动发邮件** | 应该由顾问手动发 — 体现个性化、体现有人情味，不是机器人 |
| 4 | **推荐次数无上限** | 控制在合理范围（累计 3 个进组），避免变成"拉人头" |
| 5 | **推荐关系自动公开展示** | 客户之间互看不到谁推荐了谁 — 这是顾问后台的私密信息 |
